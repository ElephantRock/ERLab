## What Changes With Source-Anchored Quotes

Currently, your WikiVerifier does this:

```
LLM: "Is claim X supported by the source?"
LLM: "Yes." → marked as SUPPORTED
```

After source anchoring:

```
LLM: "Is claim X supported by the source? Quote the exact text."
LLM: "Yes. Supporting quote: 'We achieve 76.15% accuracy on ImageNet'"
System: Does "We achieve 76.15% accuracy on ImageNet" appear in source_text?
  → YES → SUPPORTED (confidence 0.95)
  → NO  → UNSUPPORTED (confidence 0.90, quote fabrication detected)
```

**Behavioral change:** A claim that previously would have been marked SUPPORTED because the LLM confidently said "yes" will now be caught if the LLM fabricated the supporting evidence. This catches the most dangerous class of errors: confident hallucinations.

**Integration point:** The `_verify_claim_with_llm()` method in `wiki/verifier.py` needs to:
1. Add `"supporting_quote"` to the JSON response schema in the prompt
2. Add a post-processing step that runs `quote.strip() in source_text` 
3. Return different status/confidence based on quote verification result

The existing `ClaimVerification` dataclass needs a `quote_verified: bool` field added. That's it for the data model change.

## What Changes With Staged Confidence

Currently, your pipeline treats all verified claims equally:

```
Claim (quality_score=0.8) → gap analysis → study design → paper draft
Claim (quality_score=0.3) → gap analysis → study design → paper draft  ← PROBLEM
```

After staged confidence:

```
Claim (trust_tier=HIGH)    → gap analysis → study design → paper draft  ✓
Claim (trust_tier=LOW)     → display only  ← STOPS HERE
Claim (trust_tier=MEDIUM)  → gap analysis → STOPPED (can't reach study design)
```

**Behavioral change:** The orchestrator now checks `claim.is_actionable_for('study_design_input')` before passing claims to the study designer. Low-trust claims can still be displayed in artifacts (you want to see them, just not act on them) but can't propagate to downstream decisions.

**Integration point:** The orchestrator's `process_paper` method needs a filter step between claim extraction and gap detection:

```python
# Before gap detection
verified_claims = [c for c in claims if c.is_actionable_for('gap_detection_input')]
gaps = gap_detector.detect(verified_claims)  # Only from trusted claims

# Before study design
trusted_gaps = [g for g in gaps if all(
    c.is_actionable_for('study_design_input') 
    for c in g.source_claims
)]
studies = study_designer.design_studies(trusted_gaps)
```

## The AdversarialDebate Question

You flagged that `adversarial_debate.py` exists but isn't wired in. This is worth a quick decision:

**Don't wire it in now.** Here's why:

1. The adversarial debate system is designed for high-stakes decisions (which paper to trust when two contradict). Your pipeline doesn't make decisions at that level yet — it generates studies, not verdicts.

2. Source-anchored quotes + staged confidence will catch 60-70% of the hallucinations that matter. Adversarial debate adds another 10-15% but at 3x the LLM cost. The ROI isn't there yet.

3. Wait until you've run the system for a month with source anchoring. You'll have data on: what percentage of claims fail quote verification, what trust tiers claims typically reach, and where the remaining errors are. Then you'll know whether adversarial debate is worth the cost.

**Recommendation:** Move adversarial debate wiring from MEDIUM to LOW. It's not that it's useless — it's that you'll have better data on whether you need it after source anchoring is running.

## One Addition to Your Roadmap

Your analysis correctly identifies that cross-paper statistical outlier detection (technique #3's missing piece) is LOW priority. But there's a simpler version worth implementing now that takes almost no effort:

**Claim count corroboration:** If three different papers report BERT achieving ~94.5% on GLUE, and a new paper claims 99.9%, flag it. You don't need means and standard deviations — just a count of how many papers report similar values.

```python
def simple_coroboration_check(claim, known_claims_db, tolerance=0.02):
    """Check if other papers report similar values for the same metric"""
    similar = [
        k for k in known_claims_db 
        if k.metric == claim.metric 
        and k.dataset == claim.dataset
        and abs(k.value - claim.value) / max(abs(k.value), abs(claim.value)) < tolerance
    ]
    
    if len(similar) >= 3 and claim.value_differs_significantly(similar):
        return f"Claim ({claim.value}) differs from {len(similar)} corroborated reports (~{similar[0].value})"
    
    return None
```

This is 20 lines of code, requires no new infrastructure, and catches outlier claims. Add it when you add source anchoring — it's essentially free.
