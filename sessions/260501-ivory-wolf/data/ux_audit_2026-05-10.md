# Elephant Rock Research Platform — UX & User Journey Audit

**Date:** 2026-05-10  
**Auditor:** ivory-wolf  
**Scope:** Full frontend — 20 pages, 83 components, 20,275 LOC  
**Methodology:** Static code analysis of all `.tsx`/`.ts` files, tracing every user-visible interaction path

---

## 1. Executive Summary

Elephant Rock's frontend is a **feature-complete research platform UI** with proper authentication, responsive layout, internationalization (9 languages), dark mode, global search, and live pipeline monitoring. The codebase demonstrates solid engineering: lazy-loaded routes, consistent component patterns, well-typed API clients, and proper error boundaries.

**The core UX problem is one of density, not absence.** The platform exposes 15 navigation items, 118 API endpoints, 4 pipeline strategies, and 258 configuration fields to a user whose primary goal is simple: *"Give me a research proposal."* The gap between what the user wants and what the UI asks them to understand is wide. A first-time user arrives at a dashboard with 15 sidebar items and no clear "Start Here" action — the onboarding overlay helps, but it was added late and its impact is diluted by the surrounding visual complexity.

**Overall UX Grade: B-** — Functionally complete, visually clean, but suffers from feature sprawl that increases cognitive load and extends time-to-value.

## 3. Page-by-Page Assessment

### 3.1 Login Page (`login.tsx` — 200 LOC)

**Rating: ✅ GOOD**

| Aspect | Assessment |
|:-------|:-----------|
| Visual clarity | Single centered card, no distractions |
| Mode switching | Login / Register / Forgot Password — clean transitions |
| Error display | Inline red text below form |
| Friction | Minimal — 2-3 fields per mode |
| Accessibility | `htmlFor`/`id` pairs, `data-testid` on all inputs |

**Issue found:** The "Forgot password?" link is plain text styled as an underline — it looks like a label, not an interactive element. No hover state beyond the underline.

### 3.2 Dashboard (`dashboard.tsx` — 240 LOC)

**Rating: ⚠️ NEEDS IMPROVEMENT**

| Aspect | Assessment |
|:-------|:-----------|
| First impression | 3 stat cards (Total Runs, Total Ideas, System) + "New Pipeline" button |
| Empty state | ✅ Good — shows FlaskConical icon + "No runs yet" message |
| Onboarding | ✅ Overlay triggers for first-time users with 0 runs |
| Analytics | Lazy-loaded charts appear only when data exists |
| Navigation to action | "New Pipeline" button is present but small (size="sm") |

**Issues:**

1. **The "New Pipeline" button is size="sm"** — it's easy to miss among 3 stat cards, 5 recent runs, and 5 recent ideas. The primary action on this page should be the most visually prominent element.

2. **Analytics charts appear only after data exists** — this means first-time users see an empty page with 3 zeroes. The charts should be replaced with a stronger call-to-action for new users.

3. **Onboarding overlay condition is fragile** — triggers only when `localStorage` flag is absent AND `runsData.total === 0`. If the user dismisses it, it never returns. No way to re-trigger onboarding.

### 3.3 Pipeline Configuration (`pipeline-new.tsx` — 341 LOC)

**Rating: ✅ GOOD (with caveats)**

| Aspect | Assessment |
|:-------|:-----------|
| Domain input | ✅ First field, clearly labeled, with placeholder examples |
| Strategy selector | ✅ Good — 4 options with time estimates and descriptions |
| Default values | ✅ Reasonable (5 gaps, 5 ideas/round, 2 rounds) |
| Advanced section | ✅ Collapsed by default — reduces initial cognitive load |
| Cancel flow | ✅ Confirmation dialog before cancelling a running pipeline |
| Result display | ✅ Ideas appear inline after completion |

**Issues:**

1. **7 form fields are visible by default** — domain, strategy, max gaps, ideas/round, generation rounds, export format, search queries. This is more than necessary for a first run. Domain + strategy would suffice; the rest should default and hide.

2. **Strategy time estimates are vague** — "~2-5 min", "~25 min", "~45 min". A first-time user sees "Deep Research (~25 min)" as the default and may not realize "Quick Scan (~3 min)" is the better first experience.

3. **No progress indication during the "Starting..." phase** — the button shows a spinner, but there's no feedback about what's happening (API call to start the pipeline).

```
│  🧩 Plugins                 │

```

**Assessment:** 15 items is **too many for a sidebar**. Cognitive science research shows 7±2 items is the sweet spot for navigation (Miller's Law). The user must scan 15 items to find what they need.

**Recommended grouping:**

```
PRIMARY (always visible):
  Dashboard  ·  Pipeline  ·  Ideas  ·  Gaps

SECONDARY (collapsible "Research Tools" section):
  Knowledge  ·  Literature  ·  Graph  ·  Memory

SYSTEM (collapsible "Administration" section):  
  Settings  ·  Costs  ·  Traces  ·  Governance  ·  Sessions  ·  Plugins  ·  Autonomous
```

### 4.2 Header Bar

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍 Search…  ⌘K          [☀/🌙] [🔔]                        │
└──────────────────────────────────────────────────────────────┘
```

**Rating: ✅ GOOD**

- Global search with `⌘K` keyboard shortcut — excellent power-user feature
- Dark mode toggle — easy access
- Notification bell — with dropdown for alerts

**Issue:** The search button is styled as `variant="outline" size="sm"` — easy to miss. The `⌘K` shortcut is discoverable via the `<kbd>` element, but only if the user looks at the button.

### 4.3 Mobile Navigation

5 items in bottom nav: Dashboard, Pipeline, Ideas, Autonomous, Plugins.

**Issue:** "Gaps" is missing from mobile navigation — it's a key output view. "Plugins" is included but is a low-priority page. This prioritization seems wrong.

### 4.4 Breadcrumb / Back Navigation

**Rating: ⚠️ INCONSISTENT**

- `run-detail.tsx` → "Back to Dashboard" (navigates to `/`)
- `idea-detail.tsx` → "Back to Ideas" (navigates to `/ideas`)
- `gap-detail.tsx` → uses `useParams` but no back button visible in code

There's no consistent breadcrumb pattern. Users rely on browser back button or the sidebar to orient themselves.

## 5. Visual Hierarchy Audit

### 5.1 Typography Scale

The platform uses Tailwind's default typography:
- Page titles: `text-2xl font-bold tracking-tight` (consistent ✅)
- Section titles: `text-lg font-semibold` (consistent ✅)
- Card titles: `text-sm font-medium` (consistent ✅)
- Body text: `text-sm` (default)
- Muted text: `text-xs text-muted-foreground`

**Assessment:** The typography is consistent and well-structured. The hierarchy is clear: page → section → card → detail.

### 5.2 Color System

```css
Light mode:  primary = blue-600, success = green-600, warning = amber-500, error = red-500
Dark mode:   primary = blue-500, success = green-500, warning = amber-400, error = red-400
```

**Assessment:** Standard, accessible color choices. Blue primary with semantic colors for status. Dark mode is properly implemented with CSS custom properties.

### 5.3 Card-Based Layout

Every page uses `Card` components with `CardHeader` + `CardContent`. This creates visual consistency but also visual monotony — every section looks the same.

**Issue:** On pages like Settings, 6 cards stacked vertically creates a "wall of cards" effect. Different visual treatments (inline sections, expandable panels) would reduce perceived complexity.

### 5.4 Empty States

Most pages have empty states with icons and messages:
- Dashboard: FlaskConical icon + "No runs yet. Start your first pipeline!" ✅
- Ideas: "No ideas found..." ✅
- Gaps: GitBranch icon + "No research gaps found..." ✅
- Autonomous: Cpu icon + "No autonomous cycles yet." ✅

**Rating: ✅ GOOD** — Consistent, friendly, actionable.

## 8. Friction Point Inventory

### 🔴 HIGH FRICTION

**F-01: 15-item sidebar with no grouping**  
All navigation items are equally weighted. A first-time user has no visual hierarchy to guide them.  
*Location:* `sidebar.tsx`  
*Impact:* Increases orientation time by ~10-15 seconds per visit.

**F-02: 7 visible form fields for first pipeline run**  
Domain, strategy, max gaps, ideas/round, generation rounds, export format, search queries — all visible at once. For a first-time user, only domain matters.  
*Location:* `run-config-form.tsx`  
*Impact:* Decision paralysis; user may abandon or accept defaults without understanding.

**F-03: No clear "recommended first action"**  
Dashboard shows "New Pipeline" as a small button among stat cards, recent runs, and recent ideas. There's no visual weight difference between browsing and creating.  
*Location:* `dashboard.tsx`  
*Impact:* User explores 3-4 pages before finding the start button.

**F-04: Deep Research as default strategy**  
The default strategy is "Deep Research" (~25 min). A first-time user commits to 25 minutes before understanding what they'll get. "Quick Scan" should be the default.  
*Location:* `run-config-form.tsx` line 45  
*Impact:* First experience is a 25-minute wait.

### 🟡 MEDIUM FRICTION

**F-05: "Consciousness State" jargon on Autonomous page**  
"Idle", "Exploring", "Reflecting" are internal system states. Users expect "Not Running", "Active", "Paused".  
*Location:* `autonomous.tsx`

**F-06: Read-only "Self-Improvement" section in Settings**  
Shows system internals (evolution overlays, outcomes) that regular users can't control. Adds noise without value.  
*Location:* `settings.tsx`

**F-07: No breadcrumb or contextual navigation**  
Users navigate via sidebar or browser back button. No breadcrumb trail, no "You are here" indicator.  
*Location:* All detail pages

**F-08: Source gap IDs are opaque strings**  
Idea detail shows `source_gap_ids` as raw strings. Should be clickable links to gap detail pages.  
*Location:* `idea-detail.tsx`

### 🟢 LOW FRICTION

**F-09: Mobile bottom nav excludes "Gaps"**  
Key output view is not accessible on mobile without using the sidebar (which is hidden on mobile).  
*Location:* `sidebar.tsx` MobileBottomNav

**F-10: Login page "Forgot password?" looks like a label**  
Underline styling is too subtle; no hover state differentiation.  
*Location:* `login.tsx`

**F-11: "Run Another" button at bottom of pipeline results**  
After a pipeline completes, the "Run Another" button is at the bottom of the results section. It should also appear at the top.  
*Location:* `pipeline-new.tsx`

## 10. Recommendations (Priority Order)

### P0 — Reduce Time-to-Value (1-2 days)

1. **Default strategy to `fast_scan`** — Change `run-config-form.tsx` line 45 from `"deep_research"` to `"fast_scan"`. New users get results in 3 minutes, not 25.

2. **Make "New Pipeline" the visual hero of Dashboard** — Increase button size, use `variant="default"` (not `outline`), position it above the stat cards, make it full-width on mobile.

3. **Collapse all but Domain and Strategy** — Move max_gaps, ideas_per_round, generation_rounds, export_format, and search_queries into the Advanced section by default for new users.

### P1 — Reduce Cognitive Load (1 week)

4. **Group sidebar into 3 sections** — Primary (Dashboard, Pipeline, Ideas, Gaps), Research Tools (Knowledge, Literature, Graph, Memory), System (Settings, Costs, Traces, Governance, Sessions, Plugins, Autonomous). Use section headers and visual dividers.

5. **Replace "Consciousness State" with human labels** — "idle" → "Not Running", "exploring" → "Researching...", "reflecting" → "Analyzing Results".

6. **Hide "Self-Improvement" section from non-admin users** — Or move it to an "Advanced" tab in Settings.

7. **Add breadcrumb navigation** — Show `Dashboard > Pipeline > Run #42` as a breadcrumb trail on detail pages.

### P2 — Improve Accessibility (1 week)

8. **Add skip-to-content link** — `<a href="#main-content" class="sr-only focus:not-sr-only">Skip to main content</a>` as the first element in AppShell.

9. **Add `aria-live="polite"` to pipeline progress** — Announce stage transitions to screen readers.

10. **Increase mobile touch targets** — Bottom nav items should be at least 44×44px (currently ~25px).
