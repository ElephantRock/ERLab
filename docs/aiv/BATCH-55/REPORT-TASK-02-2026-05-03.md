# BATCH-55 TASK-02: Fix list_runs Serialization Crash

**Date**: 2026-05-03
**Status**: DONE

## Problem

`GET /api/v1/pipeline/runs` could crash due to lazy-loaded `r.ideas` relationship causing a `DetachedInstanceError` or similar serialization issue when SQLAlchemy objects were accessed after the session context closed.

## Changes

### `backend/db/crud.py`

1. **Added eager loading of `ideas` relationship in `list_pipeline_runs()`** — Added `selectinload(PipelineRun.ideas)` to the query so the ideas are fetched in the same query, preventing lazy-load issues when `len(r.ideas)` is called in the route handler.

2. **Fixed `completed_at` for failed runs** — `update_pipeline_run()` now sets `completed_at` for both `"completed"` and `"failed"` statuses, ensuring failed runs have proper completion timestamps.

### `backend/db/database.py`

The `expire_on_commit=False` was already correctly configured — no change needed.

## Tests

Created `backend/tests/test_api/test_batch55_task02.py` with 2 tests:
- `test_55_02_01_list_runs_returns_200` — Verifies GET /runs returns 200 with valid data
- `test_55_02_02_runs_with_ideas_return_correct_ideas_count` — Verifies runs with ideas return correct `ideas_count`

All tests pass.
