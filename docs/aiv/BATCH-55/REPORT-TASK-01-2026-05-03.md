# BATCH-55 TASK-01: Fix Pipeline Background Task Error Handling

**Date**: 2026-05-03
**Status**: DONE

## Problem

When the orchestrator's `run()` method threw an exception, the `_run_pipeline()` inner function in `backend/api/routes/pipeline.py` caught it and fired webhooks/notifications, but did NOT update the DB run record to `status="failed"`. The orchestrator had internal error handling for specific cases (e.g., "No papers found"), but if an exception occurred before reaching that point, the DB status stayed "running" forever.

## Changes

### `backend/api/routes/pipeline.py`

1. **Added `timezone` to datetime import** — Changed `from datetime import datetime` to `from datetime import datetime, timezone` to support `datetime.now(timezone.utc)`.

2. **Added DB failure update in `_run_pipeline()` except block** — When the orchestrator throws an exception, the except block now:
   - Opens a new DB session
   - Queries for the most recent `PipelineRun` with `status="running"`
   - Sets `status="failed"`, `error_message=str(e)[:500]`, and `completed_at=datetime.now(timezone.utc)`
   - Commits the change
   - Wraps the entire DB update in its own try/except to avoid masking the original error

### `backend/db/crud.py`

3. **Fixed `update_pipeline_run()` to set `completed_at` on failed status** — Previously only set `completed_at` when `status == "completed"`. Now sets it for both `"completed"` and `"failed"` statuses.

## Tests

Created `backend/tests/test_api/test_batch55_task01.py` with 3 tests:
- `test_55_01_01_pipeline_failure_updates_db_status_to_failed` — Verifies DB status set to "failed"
- `test_55_01_02_pipeline_failure_sets_error_message` — Verifies error_message is populated
- `test_55_01_03_pipeline_failure_sets_completed_at` — Verifies completed_at is set to a datetime

All tests pass.
