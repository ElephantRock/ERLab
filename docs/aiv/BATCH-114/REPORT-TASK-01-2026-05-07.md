## 6. Failure Verification (Critical Task)

### HB-01: Deepening failure does not halt pipeline
**Test:** `test_114_01_02_hb01_non_blocking`
**Mechanism:** A `MagicMock` deepener is injected whose `deepen` method is an `AsyncMock(side_effect=RuntimeError("LLM down"))`. The test asserts:
1. `stage.execute(ctx)` does **not** raise
2. Return value is `True` (pipeline continues)

**Verified:** The `ProposalDeepeningStage.execute()` method wraps each per-proposal deepening in `try/except` and the overall stage in an outer `try/except`. Both log warnings and continue. ✅

### HB-02: Original proposal text unchanged
**Test:** `test_114_01_05_hb02_original_unchanged`
**Mechanism:** `original_md` is captured before `stage.execute()`. After execution, `proposals[0].content_md == original_md` is asserted with strict equality.

**Verified:** The stage writes only to `proposal.metadata` (JSON field), never to `content_md`, `title`, `abstract`, or any text field. ✅
