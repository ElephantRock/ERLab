## Design Decisions

1. **No schema change (per blueprint HB):** Mechanical metrics are stored within the existing `novelty_report` JSON column under a `mechanical_metrics` key, avoiding any database migration.

2. **Pipeline stage ordering:** `MechanicalMetricsStage` runs after `feasibility_scoring` and before `proposal_synthesis`, so all prior data (ideas, papers, gaps, novelty/feasibility reports) is available.

3. **API extraction:** The `GET /ideas/{id}` endpoint pops `mechanical_metrics` out of the `novelty_report` dict and returns it as a separate top-level key in the response, keeping the response clean.

4. **Composite score (informational):** Computed and logged during stage execution using:
   ```
   composite = 0.4 * llm_score + 0.3 * avg(mechanical_metrics) + 0.3 * (novelty + feasibility) / 2
   ```
