## Changes Implemented

### Backend: GET /api/v1/status/detailed
- Returns `{ version: "0.1.0", provider: string, db_status: "ok"|"error" }`
- `version` hardcoded to match health endpoint version
- `provider` from `settings.default_provider`
- `db_status` checks SQLAlchemy engine connectivity with `SELECT 1`

### Frontend: API Client Additions
1. **`testConnection(baseUrl?)`** — calls `/health` endpoint for reachability
   - Returns `{ ok: true, version }` or `{ ok: false, error }`
   - Works with custom base URL or stored URL
2. **`getDetailedStatus()`** — calls `/api/v1/status/detailed`
   - Returns `DetailedStatus` type (version, provider, db_status)

### Frontend: Settings Page Enhancements
1. **Test Connection button** — triggers `testConnection()`
   - Shows "Testing..." while in progress, disabled during test
2. **Status dot indicator**:
   - 🟢 Green (`bg-green-500`) when connected
   - 🔴 Red (`bg-red-500`) when connection fails
   - 🟡 Yellow pulse (`bg-yellow-500 animate-pulse`) while testing
   - ⚪ Gray (`bg-gray-400`) when idle (not yet tested)
   - Includes `aria-label` for accessibility
3. **Backend Info card** — shows version and provider from `/status/detailed`
   - Fetched on mount via `useEffect`
   - Shows "—" when unavailable (non-fatal)
4. **Default Research Domain** — input field
   - Saved to `localStorage` under key `erock_default_domain`
   - Loaded from localStorage on component mount
   - Can be used by pipeline form for pre-fill (AR-02)
