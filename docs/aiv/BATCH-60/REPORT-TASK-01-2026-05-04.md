# Task Implementation Report: BATCH-60/TASK-01

## Summary

Fixed the `ERR_MODULE_NOT_FOUND` error for `@sentry/react` in the Vitest test environment, which caused all 71 frontend test files to fail. The fix involved adding a global `vi.mock("@sentry/react", ...)` in the test setup file and increasing the Vitest `testTimeout` to accommodate slow jsdom component rendering.

## Problem

All 71 frontend test files (339 tests) failed with `ERR_MODULE_NOT_FOUND` when the test runner tried to resolve `@sentry/react` via `frontend/src/lib/sentry.ts` → `frontend/src/main.tsx`. The `@sentry/react` package was not installed as a dev dependency and should not be required for tests.

## Root Cause

1. **Primary**: No global mock for `@sentry/react` in the Vitest setup file. Only `sentry.test.ts` had a local `vi.mock()`, but all other test files importing components that transitively reached `main.tsx` → `sentry.ts` failed at module resolution.
2. **Secondary**: 5 tests (in 5 separate files) exceeded the default 5000ms Vitest test timeout due to heavy jsdom rendering of complex React components.

## Changes Made

### File 1: `frontend/src/test/setup.ts` (modified)

Added global `vi.mock("@sentry/react", ...)` with stub implementations for all Sentry SDK functions used by the codebase:

- `init`, `captureException`, `captureMessage`
- `withScope` (with nested `setUser`, `setTag`, `setExtra`, `setLevel`)
- `setUser`, `setTag`, `setExtra`, `setContext`, `addBreadcrumb`
- `startTransaction` (with nested `startChild`, `finish`, `setStatus`, `setData`)
- `showReportDialog`, `lastEventId`, `flush`, `close`

This mock exists **only** in the test setup file and does **not** intercept any production code paths (HB-01 satisfied).

### File 2: `frontend/vitest.config.ts` (modified)

Added `testTimeout: 15_000` to the test configuration. The default 5000ms was insufficient for 5 tests that render complex React components (Sidebar, IdeasBrowser, IdeaDetail, RunConfigForm) with Radix UI primitives in jsdom.

## Files NOT Modified (HB-01 / AC-01-02)

- `frontend/src/lib/sentry.ts` — Production Sentry init logic untouched
- `frontend/src/main.tsx` — No conditional import guard needed
- `frontend/src/components/error-boundary.tsx` — Untouched
- No existing passing tests were broken (HB-03 satisfied)
