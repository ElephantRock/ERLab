## Summary

Added exponential backoff retry logic for arXiv HTTP 429 (rate-limit) responses in `ArxivSource.search()`. The implementation retries up to 3 times with backoff delays of 5s → 15s → 30s, while preserving the existing 3-second pre-request delay. Non-429 HTTP errors fail immediately without retry.

## Implementation Details

### `backend/pipeline/literature/arxiv_source.py`

- Added class constants `BACKOFF_DELAYS = [5, 15, 30]` and `MAX_RETRIES = 3` to `ArxivSource`.
- Wrapped `self._client.get()` in a `for attempt in range(self.MAX_RETRIES + 1)` retry loop inside the existing `try/except` block.
- On HTTP 429: if retries remain, sleep with `BACKOFF_DELAYS[attempt]` and `continue`; if retries exhausted, log warning and return `[]`.
- On any non-429 status: call `response.raise_for_status()` immediately (no retry). If it raises, the existing `except httpx.HTTPError` handler catches it and returns `[]`.
- On success (2xx): `return self._parse_feed(response.text)` immediately.
- Preserved the existing `await asyncio.sleep(3)` pre-request rate-limit delay before the loop.
- `get_paper()` method unchanged per task spec (lower priority, less frequent calls).
