### Key Design Decisions

1. **MockLLMProvider** — A custom `LLMProvider` subclass that inspects the JSON schema of each call to detect which pipeline stage is invoking it and returns deterministic, stage-appropriate responses:
   - Gap analysis → returns 2 research gaps with titles, descriptions, gap types, and confidence scores
   - Idea generation → returns 2 research ideas with full metadata
   - Novelty checking → returns scores (0–1 range) for method, problem, domain transfer, and combination novelty
   - Feasibility scoring → returns 6 dimension scores (0–10 range) plus overall score
   - Proposal synthesis → returns a full proposal with abstract, introduction, method, evaluation plan, references

2. **No API keys required** — All external services (LLM, embeddings, vector store) are mocked
3. **No `@pytest.mark.integration` or `@pytest.mark.slow`** — Runs in normal CI
4. **All optional subsystems disabled** via minimal `Settings` (memory, governance, budget, etc.)

### Test Coverage

| Test | What It Verifies |
|------|-----------------|
| `test_full_pipeline_all_stages` | Executes stages 1–8 in order, verifying each produces correct output |
| `test_mock_provider_returns_deterministic` | Confirms MockLLMProvider returns identical results on repeated calls |
| `test_mock_provider_handles_all_stages` | Validates mock responses conform to each stage's expected schema |

### Stage Assertions

- **Stage 1 (Literature Search):** ≥5 papers found
- **Stage 3 (Gap Analysis):** ≥1 gap with title and description
- **Stage 4 (Idea Generation):** ≥1 idea with title and proposed_method
- **Stage 5 (Novelty Checking):** ≥1 report with `overall_score ∈ [0, 1]`
- **Stage 6 (Feasibility Scoring):** ≥1 report with `overall_score ∈ [0, 10]`
- **Stage 7 (Proposal Synthesis):** ≥1 proposal with markdown > 50 chars
- **Stage 8 (Export):** ≥1 file written to disk with content > 50 chars
