## Summary

Each proposal synthesis call is now wrapped in `asyncio.wait_for()` with a configurable per-proposal timeout (default 120s, hard cap 300s). On timeout, a placeholder `ResearchProposal` is saved and the loop continues to the next idea — a single slow LLM call can no longer block the entire batch.

## Changes

### 1. `backend/config.py` (modified)
- Added `per_proposal_timeout: float = 120.0` setting alongside existing stage-level execution settings (line ~310).

### 2. `backend/pipeline/stages.py` (modified)
- Added `import asyncio` to top-level imports.
- Added `from backend.pipeline.synthesis.proposal_synthesizer import ResearchProposal` for placeholder creation.
- Rewrote `ProposalSynthesisStage._execute_synthesis()`:
  - Reads `per_proposal_timeout` from settings, caps at 300s via `min(timeout, 300.0)`.
  - Each `self._synthesizer.synthesize()` call is wrapped in `asyncio.wait_for(call, timeout=timeout)`.
  - On `asyncio.TimeoutError`: logs warning, creates placeholder `ResearchProposal(title=idea.title, abstract="Synthesis timed out after {timeout}s", introduction="Timed out", proposed_method=idea.proposed_method)`, and continues the loop.
