# BATCH-57 TASK-02: Fix Pipeline Completion Metadata

**Date:** 2026-05-03
**Status:** ✅ COMPLETE

## Problem

Completed pipeline runs had `completed_at=NULL`, `stages_completed=[]`, and `current_stage` stuck at `"initializing"`.

## Root Cause

1. `mark_run_completed()` called `crud.update_pipeline_run()` with only `status="completed"` — never passed `current_stage="completed"`.
2. `mark_run_failed()` similarly omitted `current_stage="failed"`.
3. No `advance_stage()` method existed to update `current_stage` and `stages_completed` during execution.
4. The orchestrator never called any stage-tracking method between stages.

## Changes

### `backend/pipeline/persistence.py`

1. **Added `advance_stage(run_id, stage_name)`** — updates `current_stage` and appends to `stages_completed` JSON array for the given pipeline run.
2. **Fixed `mark_run_completed()`** — now passes `current_stage="completed"` in addition to `status="completed"`. The underlying `crud.update_pipeline_run()` already sets `completed_at` when status transitions to `"completed"`.
3. **Fixed `mark_run_failed()`** — now passes `current_stage="failed"` alongside `status="failed"` and `error_message`.

### `backend/pipeline/orchestrator.py`

1. Added `self._persistence.advance_stage(db_run_id, stage.name)` call **before** each stage executes in the main `run()` loop, so `current_stage` always reflects the active stage.

### Database cleanup

- Updated stuck Run 16: `status='failed'`, `error_message='Cleaned up during BATCH-57'`, `completed_at=now`.

### `backend/tests/test_pipeline/test_batch57_task02.py`

- `test_57_02_01_advance_stage_updates_current_stage` — verifies `advance_stage` sets `current_stage` and appends to `stages_completed` JSON.
- `test_57_02_02_mark_completed_sets_timestamp` — structural verification.
