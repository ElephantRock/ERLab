# BATCH-31 TASK-01 Report: SSE Auth Fix

**Status**: ✅ Complete | **Commit**: `feat(batch-31/task-01)`
**Date**: 2026-05-02

## Summary

Replaced URL query parameter-based SSE authentication with header-based authentication using fetch-based SSE. This eliminates API key exposure in URLs (HB-01).

## Changes

### Frontend
- **`frontend/src/api/client.ts`**: Replaced `sseUrl()` (which appended `?api_key=...` to URLs) with `sseFetch()` that uses `fetch()` with `X-API-Key` header. SSE events are parsed from the ReadableStream.
- **`frontend/src/hooks/useSSE.ts`**: Replaced native `EventSource` with `sseFetch()`. Retained reconnect logic with exponential backoff.
- **`frontend/src/api/__tests__/client.test.ts`**: Updated tests from `sseUrl` to `sseFetch`, verifying no API keys in URLs (HB-01).

### Backend
- **`backend/api/routes/pipeline.py`**: Added explicit auth header validation in the SSE `run_progress` endpoint (defence-in-depth). Checks `X-API-Key` when `api_key` is configured, and `Authorization: Bearer` when `auth_enabled=True`.
- **`backend/tests/test_api/test_batch31_sse_auth.py`**: 4 new tests.
