# BATCH-52 TASK-02: Error Monitoring Integration (Sentry)

**Date:** 2026-05-03
**Status:** ✅ COMPLETE

## Objective
Integrate Sentry SDK for error monitoring in both backend (FastAPI) and frontend (React), with graceful fallback when DSN is not configured.

| `backend/api/app.py` | Wired `init_sentry()` into the startup event handler |
| `backend/tests/test_api/test_batch52_task02.py` | 3 tests: empty DSN → False, ImportError → False, is_sentry_initialized state |

### Frontend

| `frontend/src/components/error-boundary.tsx` | Added `Sentry.captureException(error)` in `componentDidCatch` |
| `frontend/src/lib/__tests__/sentry.test.ts` | 2 tests: empty DSN → false, DSN set → true + init called |

### Design Decisions
- **Opt-in by default**: Both backend and frontend Sentry are completely disabled when DSN is empty (the default). No env var = no telemetry.
- **Graceful degradation**: `init_sentry()` catches `ImportError` if `sentry-sdk` is not installed.
- **Error Boundary integration**: All unhandled React errors are captured via `componentDidCatch` → `Sentry.captureException()`.
- **Low overhead**: `traces_sample_rate=0.1` by default (10% of transactions traced).
