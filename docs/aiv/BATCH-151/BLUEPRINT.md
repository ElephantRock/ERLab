───────────────────────────────────────────────────────────
BATCH GOAL
───────────────────────────────────────────────────────────

Ship a one-command `docker compose up` deployment that starts the Elephant Rock
backend (FastAPI), frontend (React/Vite), and SQLite database in production-ready
configuration, plus add AI-generated honesty labeling to all exported proposals.

───────────────────────────────────────────────────────────
SCOPE STATEMENT
───────────────────────────────────────────────────────────

What the code MUST do:
  - Provide a Dockerfile.backend that builds the Python FastAPI server
  - Provide a Dockerfile.frontend that builds the React/Vite app and serves it via Nginx
  - Provide a docker-compose.yml that orchestrates backend + frontend + volume mounts
  - Backend Dockerfile MUST install all pip dependencies, run Alembic migrations on startup,
    and start uvicorn with production-appropriate workers
  - Frontend Dockerfile MUST build the Vite production bundle and serve via Nginx with
    API proxy to backend
  - docker-compose.yml MUST expose port 3000 (frontend) and 8000 (backend API)
  - A persistent named volume MUST store the SQLite database across container restarts
  - An .env.docker example file MUST be provided with all EROCK_ variables documented
  - All exported proposals (Markdown, PDF, BibTeX, LaTeX) MUST include an AI-generated
    honesty badge: "This research proposal was generated by an AI pipeline. Claims
    should be independently verified."
  - The AI honesty badge MUST be appended to the proposal synthesis output as a final
    section with a horizontal rule separator

What the code MUST NOT do:
  - MUST NOT modify existing pipeline stages, orchestrator, or core business logic
  - MUST NOT change any existing API endpoint signatures
  - MUST NOT require Docker for development (existing `python -m uvicorn` + `npm run dev`
    workflow MUST continue to work unchanged)
  - MUST NOT hardcode any secrets, API keys, or model names in Docker files
  - MUST NOT add any new Python or npm dependencies (use existing requirements.txt
    and package.json as-is)
