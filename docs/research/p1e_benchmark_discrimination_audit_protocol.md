# P1E.0 — Benchmark Discrimination Audit Protocol (FROZEN)

```text
P1E.0 protocol       FROZEN
P1E.0 implementation AUTHORIZED
P1E.1                BLOCKED pending audit acceptance
P1                   OPEN
P2                   BLOCKED
```

> **Mission.** Determine whether the frozen P1B benchmark can meaningfully
> distinguish retrieval and ranking quality, or whether its high scores
> primarily reflect ceiling effects, weak negatives, limited judgment
> resolution, or insufficient statistical power.

This document is the **preregistered protocol**. It is frozen in Commit 1
*before* any measurement. Every generated P1E artifact embeds the SHA-256 of
this file and of `data/evaluation/p1e_frozen_split_manifest.json`. If either
changes after measurement begins, all audit outputs are stale and must be
regenerated.

## 3. Graded-relevance categories

```text
grade 0      nonrelevant candidate
grade 1      weakly relevant candidate
grade >= 2   strongly relevant candidate
```

P1B treats every grade greater than zero as relevant. Therefore **hard-negative
statistics use grade 0**; grade-1 confusers are reported separately as
weak-positive ambiguity (§6).

```text
top_grade      = max(candidate final grades in a case)
unique_best    = exactly one candidate has top_grade  AND  top_grade > 0
ambiguous_top  = two or more candidates share top_grade  AND  top_grade > 0
```

Grade-3 counts are still reported, but unique-best is defined by the maximum
observed grade, not by grade 3 specifically. A case with no grade 3 but one
uniquely best grade-2 candidate is `unique_best`.

## 4. Oracle, headroom, and metric resolution

### 4.1 Oracle

The oracle metric for a case is computed by feeding the **ideal descending**
grade ordering through the **original** metric functions
(`_ndcg_at_k`, `_mrr_at_k`, `_precision_at_k`, `_recall_at_k`). No new metric
formula is introduced. All-zero-grade cases inherit the original function's
behavior (e.g. nDCG returns 0.0 because IDCG=0); they are flagged `all_zero`
and are never silently assigned perfect performance.

### 4.2 Headroom

Two headroom values per case per metric:

```text
historical_headroom = oracle_metric - best_P1B_policy_metric
observed_headroom   = oracle_metric - best_result_across_the_five_unique_runs
```

`observed_headroom` drives the saturation diagnosis. Using historical headroom
alone would ignore a TEI run that already consumes part of the headroom.

### 4.3 Metric resolution (empirical)

Resolution is computed empirically, not by a closed-form denominator. For each
case:

```text
take the canonical ideal grade ordering
enumerate every ADJACENT swap of DIFFERENTLY-GRADED candidates
recompute the per-case metric through the original metric functions
```

The effective macro resolution for a metric is the **minimum nonzero absolute
macro change** across all legal single-case adjacent-swap perturbations
(per-case change / 44), reported separately for nDCG@5, MRR@10, P@5, Recall@20,
and **top1_optimal**. Equal-grade swaps do not count.

For `top1_optimal`, all-zero cases are **excluded from the denominator**; the
effective denominator is reported explicitly. All-zero cases never count as
automatically optimal.

## 5. The five-run matrix

Five unique ranking runs (lexical is snapshot-independent):

```text
1  legacy_lexical_top20_v1   (snapshot-independent)
2  semantic_only_v1          (P1B snapshot)
3  semantic_only_v1          (TEI snapshot)
4  hybrid_rrf_v1             (P1B snapshot)
5  hybrid_rrf_v1             (TEI snapshot)
```

`observed_headroom` = oracle − best of these five. The audit names this the
"five-run matrix" consistently across all artifacts.

### 5.1 Required pairwise comparisons

```text
lexical            vs P1B semantic
lexical            vs TEI semantic
P1B semantic       vs TEI semantic
P1B hybrid-RRF     vs TEI hybrid-RRF
```

For each comparison report: top-1 candidate agreement, top-1 relevance-grade
agreement, `top1_positive`, `top1_optimal`, top-5 set overlap (Jaccard),
full-ranking Kendall-tau and Spearman, per-query nDCG@5 delta, per-query
MRR@10 delta, and pairwise win/loss/tie on per-query nDCG@5.

### 5.2 Pairwise classification labels

```text
positive_delta   nDCG@5(b) - nDCG@5(a) >  0
negative_delta   nDCG@5(b) - nDCG@5(a) <  0
tie              nDCG@5(b) - nDCG@5(a) == 0
```

"Material" is reserved for movement exceeding the preregistered effect
threshold **|delta| > 0.0150** on nDCG@5. `|delta| > 0` is NOT material; it is
merely a positive/negative delta.

### 5.3 Ranking correlation

Kendall-tau and Spearman are computed over the **identical candidate universe**
(all case candidates; every policy ranks the full candidate tuple, so the
universe is guaranteed identical). The comparison explicitly covers **all case
candidates**, not the first `FROZEN_FINAL_LIMIT`. A candidate ID missing from
either ranking produces an **integrity failure**, not an implicit tail
assignment.

## 6. Hard-negative coverage

### 6.1 Hierarchy (frozen)

```text
case-relative grade-0 analysis     PRIMARY
grade-1 ambiguity analysis         SECONDARY
global fixed-threshold analysis    SENSITIVITY ONLY (never drives S/A)
```

### 6.2 PRIMARY grade-0 hard negative

```text
grade == 0
AND ( lexical overlap  >= min overlap  among grade > 0 candidates
   OR P1B similarity   >= min P1B sim  among grade > 0 candidates
   OR TEI similarity   >= min TEI sim  among grade > 0 candidates )
under at least one corresponding scorer
```

Baseline is **grade > 0** (all relevant candidates), not grade >= 2. For each
primary hard negative also report whether it:

```text
outranks any grade > 0 candidate   (under a named policy)
outranks the highest-grade candidate
ranks first                        (under a named policy)
```

Cases with no grade-positive candidate are `all_zero` and cannot supply a
relative hard-negative baseline.

### 6.3 Secondary analyses (reported, not diagnosis-driving)

```text
strong-positive confuser -> grade == 0 -> competes with or outranks a grade >= 2 candidate
weak-positive ambiguity  -> grade == 1 -> competes with a higher-grade candidate
score margin to nearest positive
```

### 6.4 Global thresholds (sensitivity only)

```text
lexical overlap >= 0.30   OR   P1B/TEI similarity >= 0.65
```

These are acceptable as a sensitivity analysis but **must not drive the S/A/M
diagnosis**. The S/A diagnosis uses the count of **unique primary grade-0 hard
negatives**. No new negatives are generated in P1E.0.

## 7. Error recurrence and architecture signal

Each of the eight named classes is labelled with one posture:

```text
classified     supported by a deterministic schema/rule
hypothesis     suggested but not causally established
count 0        no supporting cases (zero is a valid result)
not-inferable  cannot be established from observable evidence
```

Named classes: lexical aliasing; generic research-language overlap; entity
mismatch; method-versus-domain confusion; task-versus-evidence mismatch;
long-document dilution; near-duplicate candidates; missing query context.

The script may identify **observable evidence patterns** but must not assert
causal failure classes without direct schema support (e.g. `near_duplicate` is
classifiable because `near_duplicate_of` is a schema field; "long-document
dilution" is at most a hypothesis). All eight classes are NOT required to
contain cases; zero is valid.

Every nonzero class must include: exact deterministic rule, case IDs,
candidate IDs, grades, ranks under named policies, relevant score margins,
and whether hybrid ranking repaired the observed ordering.

Each failure is classified as: model-specific / shared by both embedding
models / shared by lexical and semantic policies / repaired by hybrid /
unrepaired by all existing policies.

## 8. Statistical power

### 8.1 Continuous metrics (nDCG@5, MRR@10)

```text
alpha                  0.05
power target           0.80
two-sided              yes
MDE method             preregistered paired-difference approximation
MDE                    (z_{1-alpha/2} + z_{power}) * sd(paired differences) / sqrt(n)
                       = (1.959964 + 0.841622) * sd(diff) / sqrt(n)
zero-variance handling MDE = 0 reported ONLY when every paired difference is
                       identical; zero-variance flagged separately so it is not
                       misread as high sensitivity
```

### 8.2 Binary top-result (top1_optimal)

```text
statistic              top1_optimal paired Bernoulli outcome
test                   exact two-sided McNemar
alpha                  0.05
power target           0.80
MDE method             deterministic simulation over discordant pairs
simulation draws       100,000
seed                   20260721
zero discordance       MDE unavailable; classify tied-heavy
```

### 8.3 Bootstrap and permutation

```text
paired resampling unit     case
iterations                  10,000
primary seed                20260721
interval                    percentile
confidence level            95%
sensitivity seed            42  (reported, never replaces primary)
permutation                 exact two-sided if feasible, else Monte-Carlo
permutation MC seed         20260721
```

### 8.4 Outcome labels (no equivalence claim)

```text
detected_difference        primary 95% CI excludes zero OR permutation p < 0.05
no_detected_difference     CI includes zero AND p >= 0.05, with adequate power
underpowered               MDE larger than a plausible effect of interest
tied_heavy                 insufficient non-tied queries to detect anything
saturated                  oracle headroom near zero (nothing to detect)
```

Non-significance does NOT prove "true equivalence." An equivalence claim
requires a protocol-frozen margin plus an equivalence test (TOST). No margin
is frozen here, so **the word "equivalence" is prohibited** in the diagnosis.
```text
adaptive statistical-method selection    0
```

## 9. Snapshot access (cal+dev allowlist)

Both snapshots are filtered **before** item materialization.

- **TEI snapshot** (`scripts/p1_embedding_snapshot_adapter.py`):
  `tei_snapshot_to_embedding_snapshot(payload, *, allowed_item_ids=None)`.
  `allowed_item_ids` = cal+dev query IDs + the candidate IDs referenced by
  cal+dev cases only. Items not in the allowlist are never decoded. Default
  `None` preserves the existing P1D behavior (used only by P1D).
- **P1B snapshot** (`backend/ranking/p1e_snapshot_filter.py`):
  `load_snapshot_filtered(snapshot_dir, *, allowed_item_ids,
  expected_benchmark_fingerprint, expected_benchmark_version)`. Reuses
  `compute_snapshot_fingerprint` and `vector_fingerprint` integrity primitives
  but decodes only allowed items; raises `SnapshotIntegrityError` if a held-out
  item_id is decoded or requested. The original `load_snapshot` is left
  untouched.

A full snapshot file may be hashed as opaque bytes (SHA-256 of the file). Its
held-out entries are never decoded or inspected.

## 10. S/A/M diagnosis (fully preregistered decision table)

Every criterion's boolean result AND measured value are published. No
composite score hides contradictory evidence. All thresholds are exact.

### 10.1 Outcome S — saturation-dominant

ALL of the following required criteria must pass, AND no architecture criterion
materially met (none of A1–A4 true):

```text
R1  observed_headroom <= 0.01   on >= 60% of cases
R2  top1_optimal == 1.0         on >= 60% of (non-all-zero) cases,
                                under EVERY principal policy (all 5 runs)
R3  < 2 unique primary grade-0 hard negatives   on >= 60% of cases
R4  no_detected_difference (nDCG@5)             on ALL 4 required pairwise comparisons
R5  for the required comparison with the LARGEST absolute mean nDCG@5 delta:
       effective non-tied cases < 22
       OR  pair-specific continuous-metric MDE > that comparison's absolute mean delta
```

R5's MDE and delta must belong to the SAME comparison (the one with the largest
|mean delta|). Do not compare a maximum delta against an unrelated comparison's
MDE. "No architecture criterion materially met" = none of A1, A2, A3, A4 is
true.

### 10.2 Outcome A — architecture-dominant

ALL of the following required criteria must pass:

```text
A1  observed_headroom > 0.05    on >= 40% of cases
A2  >= 2 unique primary grade-0 hard negatives   on >= 40% of cases
A3  >= 2 recurring policy-specific error classes (posture 'classified'),
    each occurring in >= 2 distinct cal+dev cases, stable across both embedding snapshots
A4  at least ONE of the 4 required pairwise comparisons simultaneously satisfies:
       effective non-tied cases >= 22
       MDE < absolute mean delta
       primary 95% CI excludes zero  OR  permutation p < 0.05
    (non-tied count, MDE, delta, CI, permutation all from the SAME comparison)
```

### 10.3 Outcome M — mixed / inconclusive

```text
both S and A complete   -> M
neither complete        -> M
```

### 10.4 Precedence (frozen, no reinterpretation)

```text
S complete, A incomplete    -> S
A complete, S incomplete    -> A
both complete               -> M
neither complete            -> M
```

A single supporting criterion from each side does NOT override a fully
satisfied A or S rule. Boundary inclusivity: a value exactly on a threshold
satisfies the `>=` / `<=` criterion as written. Missing data counts as a
criterion failure.
